# Выбор стека

Установка Arch состоит из нескольких независимых решений. Каждое можно принять по-своему, но не все сочетания работают: ниже у каждого выбора есть плюсы, минусы и подсказка, когда его брать, а в конце таблица ограничений и готовые наборы.

**★** отмечает мой выбор. Все ★ совместимы друг с другом, поэтому если идти только по ним, получится моя система один в один.

> Это каркас нового гайда. Главы с командами пока в работе, статус в [оглавлении](README.md). Выбор здесь определяет, какие модули вы будете читать дальше.

## 1. Загрузка

Два независимых вопроса: **что запускает ядро** (загрузчик) и **в каком виде лежит ядро** (классические файлы или UKI, единый образ).

### Формат ядра

| Вариант | За | Против |
|---|---|---|
| ★ **UKI** (ядро + initramfs + параметры в одном `.efi` на ESP) | один файл, параметры вшиты и не правятся из меню, образ можно подписать для Secure Boot, проще загрузчику | параметры меняются только пересборкой (`mkinitcpio -P`); ESP нужен побольше (около 1 ГиБ); при откате снимка Btrfs образ на ESP остаётся новым (см. таблицу ограничений) |
| **Классика** (`vmlinuz` + `initramfs` в `/boot`) | привычно, параметры правятся в меню загрузчика, любое руководство подходит | больше файлов; чтобы загрузчик их видел, `/boot` должен быть читаем им (на ESP или в корне, который он умеет читать) |

### Загрузчик

| Вариант | За | Против | Когда брать |
|---|---|---|---|
| ★ **Limine** | один файл на ESP, простой конфиг, красиво настраивается, UKI запускает прямо | молодой проект, меньше статей и примеров | современная UEFI-машина, UKI |
| **systemd-boot** | уже есть в systemd, сам находит UKI в `EFI/Linux`, минимум настроек | читает только FAT, поэтому классические ядра должны лежать на ESP; меню скромное | самый простой путь с UKI |
| **GRUB** | умеет почти всё: BIOS и UEFI, много ОС, снимки Btrfs в меню (`grub-btrfs`) | большой, сложный конфиг; шифрованный `/boot` на LUKS2 работает только с PBKDF2 (не с argon2id по умолчанию); UKI запускается через `chainloader` | BIOS-машины, несколько ОС, нужен выбор снимков в меню |
| **EFISTUB** (без загрузчика: прошивка сама запускает UKI через `efibootmgr`) | нет лишнего ПО, самая короткая цепочка | нет меню, запасных записей столько, сколько создашь вручную; часть прошивок теряет записи NVRAM | стенды, виртуальные машины, минимализм |

## 2. Шифрование

| Вариант | За | Против | Когда брать |
|---|---|---|---|
| ★ **LUKS2** | данные нечитаемы при потере устройства; почти без потери скорости на современных процессорах (AES-NI) | пароль при каждой загрузке; потерянный заголовок или пароль означает потерянные данные; шифрование позже без пересоздания разделов не добавить | ноутбуки и всё, что выходит из дома |
| **Без шифрования** | проще, ничего не спрашивает при загрузке, легче восстановление | при потере устройства данные доступны | виртуальные машины, стенды, стационарный ПК в защищённом месте |

Дополнительно к LUKS (по желанию, отдельные модули): **TRIM через LUKS** (`rd.luks.options=discard`: быстрее и бережнее к SSD, но раскрывает, какие блоки свободны) и **TPM2-разблокировка** (`systemd-cryptenroll`: пароль не нужен при штатной загрузке, нужен Secure Boot и аккуратность).

## 3. Слои хранилища и файловая система

Слои идут снизу вверх: раздел → (LUKS) → (LVM) → файловая система.

### LVM

| Вариант | За | Против |
|---|---|---|
| ★ **LVM** | размеры томов (корень, swap) меняются позже; swap отдельным томом даёт гибернацию | ещё один слой; нужен хук `lvm2` в initramfs |
| **Без LVM** | проще; swap-файл вместо тома | гибернация через swap-файл настраивается тоньше, размеры разделов жёстче |

### Файловая система корня

| Вариант | За | Против | Когда брать |
|---|---|---|---|
| ★ **Btrfs** | подтома, сжатие, мгновенные снимки (Snapper), контрольные суммы | обычный swap-файл не работает (нужен `btrfs filesystem mkswapfile`); копирование-при-записи замедляет базы данных и образы ВМ (для них отключают CoW); откат снимка тоже требует внимания (см. таблицу) | рабочая машина, нужны откаты |
| **ext4** | самая простая и проверенная, быстрый `fsck`, любое руководство подходит | нет снимков и сжатия | серверы, стенды, «поставил и забыл» |
| **XFS** | быстрая на больших файлах и параллельной работе | нельзя уменьшить; снимков нет | большие данные, рабочая станция с упором на скорость |

Подтома моей схемы Btrfs: `@` (корень), `@home`, `@var_log`, `@var_cache`, `@snapshots`. Откат `@` не трогает личные данные и снимки.

**Порядок для Btrfs со Snapper: сначала Snapper, потом fstab.** Конфиг Snapper создаётся сразу после `pacstrap`, до `genfstab`: при создании Snapper делает вложенный подтом `.snapshots` внутри `@`, а нужен отдельный `@snapshots` рядом, чтобы откат `@` не уничтожил снимки. Поэтому подтом переносится, монтируется в `/mnt/.snapshots`, и только затем `genfstab` записывает его в `/etc/fstab` сразу правильно. `snap-pac` в chroot не ставится, его хук без работающего Snapper падает: он ставится после первой загрузки.

## 4. Swap

| Вариант | За | Против |
|---|---|---|
| ★ **zram + swap-том** | zram быстрый для обычной работы, том нужен для гибернации и переполнения | нужен LVM, под том отдаётся место на диске |
| **Только zram** | ничего не занимает на диске | гибернации нет; при нехватке памяти сжатие кончается |
| **Swap-файл** | не нужен отдельный раздел или том, размер меняется | на Btrfs нужен `mkswapfile` и `resume_offset` для гибернации |
| **Swap-раздел** | просто, гибернация работает | размер зашит в таблицу разделов |

## 5. Рабочая среда консоли

### Оболочка

| Вариант | За | Против |
|---|---|---|
| ★ **fish** (из `.bashrc`, login остаётся bash) | подсказки и подсветка из коробки, мало настроек | синтаксис не POSIX: готовые скрипты и команды из интернета часто не подходят |
| **zsh** | совместим с POSIX в основном, огромная экосистема плагинов | без настройки скромный; плагины ставишь сам |
| **bash** | есть сразу, всё работает | минимум удобств |

### Редактор

| Вариант | За | Против |
|---|---|---|
| ★ **neovim** | быстрый, расширяемый, мои настройки в репозитории | порог входа |
| **vim** | то же основное, есть почти везде | настройки «с нуля» |
| **nano** | ничего учить не нужно | мало возможностей |

Выбор редактора меняет `EDITOR` в `/etc/environment` и команды вроде `visudo`: в модулях это указано.

### Ядро

★ **`linux` + `linux-lts`**: LTS как запасное ядро вместо fallback-образа. Можно взять `linux-zen` (отзывчивость) или `linux-hardened` (защита ценой совместимости), но запасное ядро другого типа остаётся хорошей идеей.

### Сеть

★ **NetworkManager + systemd-resolved** (Wi-Fi и VPN удобно из `nmcli`) или **systemd-networkd + iwd** (легче, но Wi-Fi руками, для серверов).

## Ограничения сочетаний

| Сочетание | Что нужно знать |
|---|---|
| UKI + откат снимка Btrfs | ядро и модули откатываются вместе с `@`, а UKI на ESP остаётся новым: версии расходятся. После отката пересобери образ (`mkinitcpio -P` из chroot). Запасное ядро LTS тут не помогает: оно откатывается вместе с корнем |
| systemd-boot + классическое ядро | systemd-boot читает только FAT: ядро и initramfs должны быть на ESP (смонтируй ESP в `/boot`, увеличь её) |
| GRUB + шифрованный `/boot` | LUKS2 только с PBKDF2 вместо argon2id; проще держать `/boot` на ESP или использовать UKI |
| GRUB + UKI | запись `chainloader` на `.efi`; плюсы UKI (подпись) сохраняются, плюс GRUB остаётся |
| EFISTUB | записи NVRAM создаются `efibootmgr`; запасное ядро означает вторую запись; держи копию в `EFI/BOOT/BOOTX64.EFI` на случай потери записей |
| Гибернация | нужен дисковый swap (том, раздел или файл) и `resume=` (для файла ещё `resume_offset`); zram отдельно не подходит |
| Swap-том | нужен LVM |
| Swap-файл на Btrfs | только через `btrfs filesystem mkswapfile` в подтоме без сжатия и CoW |
| Secure Boot | с UKI удобнее всего (`sbctl` подписывает образ и загрузчик); официальный ISO с включённым Secure Boot не грузится |
| mkinitcpio | гайд использует initramfs на systemd (`systemd`, `sd-vconsole`, `sd-encrypt`) везде: так одинаково для всех сочетаний |

## Готовые наборы

| Набор | Шифрование | Слои и ФС | Загрузка | Swap | Для чего |
|---|---|---|---|---|---|
| ★ **Мой** | LUKS2 | LVM + Btrfs | UKI + Limine | zram + том (гибернация) | ноутбук, откаты |
| **Простой** | LUKS2 | ext4 | UKI + systemd-boot | zram | ноутбук без излишеств |
| **Классика** | LUKS2 | LVM + ext4 | GRUB, обычные ядра | том | привычный Arch, несколько ОС |
| **Стенд** | нет | ext4 | UKI + EFISTUB | zram | виртуальная машина, проверки |

## Что проверено

Пока ни один модуль не прогнан установкой в виртуальной машине. Когда проверка будет (QEMU + OVMF), рядом с каждым модулем появится отметка и дата, а непроверенное будет помечено явно. Для сверки всегда держите открытой [ArchWiki](https://wiki.archlinux.org/title/Installation_guide).
