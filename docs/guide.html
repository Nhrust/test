Arch Linux: гайд 4.1

От пустого диска до комфортной консоли, затем по желанию графика. Гайд общий, как ArchWiki: у каждого шага есть варианты, объяснение и ссылка, где копнуть глубже. Мой путь ★ проведён через весь текст: если идти только по ★, получится моя база один в один.

Как пользоваться

Варианты показаны рядом: на каждой развилке выбери один (★ мой) и пропусти остальные. Три части:

  1. I · База до TTY. Чистая установка Arch руками до входа в консоль.
  2. II · Комфортный TTY. Шрифт, fish, инструменты, файрвол, Ly. Всё руками, без скриптов. Это «моя база», воспроизводимая одинаково на любой машине.
  3. III · Графика. Любая своя среда или мой путь: Niri и GUI с настройками, палитрой и цветами консоли одним deploy.sh.

Диск будет стёрт. Команды разрушают данные выбранного диска. Если на нём есть другая ОС, не трогай чужие разделы и ESP (см. шаг 5). Каждый шаг проверяй через lsblk -f. Не публикуй UUID, пароли, имена машин и пользователей (приложение A).

Карточка установки

Заполни один раз: значения подставятся во все команды ниже (они подсвечены цветом). Ничего не сохраняется и не отправляется.

Раздел ESP: {{P1}}, системный раздел: {{P2}}. У NVMe и MMC добавляется p.

Часть I · база до TTY

1 · ISO и проверка

Wiki: Installation guide: Acquire an installation image

Образ берётся только с archlinux.org/download: через magnet-ссылку (торрент проверяет части сам) либо с зеркала. Сохрани рядом файл подписи .sig с официальной страницы, не с произвольного зеркала.

gpg --verify archlinux-YYYY.MM.DD-x86_64.iso.sig archlinux-YYYY.MM.DD-x86_64.iso

Ожидается Good signature, а отпечаток ключа должен совпасть с опубликованным на странице загрузки. Предупреждение «ключ не доверенный» само по себе не означает подделку, но отпечаток сверить нужно. Если ключа нет, его получают по WKD (команда есть на странице загрузки). Контрольные суммы:

sha256sum archlinux-YYYY.MM.DD-x86_64.iso
b2sum archlinux-YYYY.MM.DD-x86_64.iso

Не продолжай, если подпись не проверяется, отпечаток другой или сумма не совпадает: удали файлы и скачай заново.

2 · Запись на флешку

Wiki: USB flash installation medium · углубиться: варианты для Windows и Ventoy

Запись идёт на весь диск флешки, не на раздел, и стирает всё на ней. Образ Arch это готовый образ диска: форматировать флешку заранее не нужно.

lsblk -o NAME,PATH,SIZE,MODEL,TRAN,TYPE,FSTYPE,MOUNTPOINTS      # найди флешку: TRAN=usb, размер, модель
sudo umount /dev/sdX1                                             # размонтируй все её разделы

Сначала только показываем, что собираемся сделать, и перепроверяем:

ISO="$HOME/Downloads/archlinux-YYYY.MM.DD-x86_64.iso"
USB=/dev/sdX
printf 'ISO: %s\nUSB: %s\n' "$ISO" "$USB"
ls -lh "$ISO"
lsblk -o NAME,PATH,SIZE,MODEL,TRAN,TYPE,MOUNTPOINTS "$USB"

/dev/sdX1 это раздел, использовать нельзя; буквальный X тоже. Только потом:

sudo dd if="$ISO" of="$USB" bs=4M status=progress oflag=sync
sync
sudo eject "$USB"

Ошибка в of= стирает другой накопитель без вопросов. Не вынимай флешку до возврата приглашения.

★ dd на Linux

Проверяемый, ничего лишнего.

вариант Windows

Rufus в режиме «DD-образ» или Ventoy (несколько ISO на одной флешке).

3 · Загрузка live-среды и проверка

Wiki: Boot the live environment · Verify the boot mode

Открой меню загрузки прошивки и выбери флешку с пометкой UEFI. Официальный ISO не грузится с включённым Secure Boot: на время установки отключи его (ключи прошивки не удаляй). В меню выбери Arch Linux install medium: откроется root-оболочка, устанавливаемой системы ещё нет.

cat /sys/firmware/efi/fw_platform_size       # 64 = UEFI x64; файла нет = загрузились в BIOS, перезагрузись в UEFI
loadkeys us                                  # раскладка (список: localectl list-keymaps)
setfont ter-v20n                             # крупнее, если экран HiDPI
timedatectl set-ntp true
timedatectl status
lsblk -o NAME,PATH,SIZE,MODEL,TRAN,TYPE,FSTYPE,MOUNTPOINTS
lspci -nn; lsusb

Запиши точную модель целевого накопителя. Если диска не видно, не размечай «похожий»: проверь режим контроллера (AHCI/RAID) в прошивке.

★ Чистая установка на весь диск

Таблица создаётся заново, старое пропадает.

вариант Рядом с другой ОС

Не пересоздавай таблицу и не форматируй существующий ESP: смонтируй его в /efi, а под систему добавь раздел в свободном месте. Резервная копия обязательна.

Старые подписи файловых систем лучше убрать, чтобы они не конфликтовали:

Для LUKS можно ещё перезаписать диск случайными данными (медленно, нужно только если важна скрытность занятого места): см. wiki «Drive preparation».

6 · Разметка (fdisk)

Wiki: fdisk · Partition the disks · EFI system partition

GPT, два раздела: ESP и один раздел под всё остальное (при шифровании он будет зашифрован, без шифрования в нём сразу файловая система или LVM). Остальное делится уже внутри (LVM, подтома), поэтому на диске больше ничего не нужно.

Размер ESP: 1 GiB хватает для двух UKI (каждый 100-200 МиБ) и загрузчика. Больше нужно только если на неё кладутся другие загрузчики.

Раздел swap создаётся не здесь, а внутри LVM (шаг 7): так его размер потом можно менять. Поэтому для гибернации нужен LVM.

7 · Шифрование, LVM и файловая система

Wiki: dm-crypt · Encrypting an entire system · LVM · Btrfs · File systems

Выбери одну схему. Три первых шифруют раздел LUKS2, различается то, что внутри; четвёртая без шифрования.

A LUKS → ext4

Самое простое. Один том, легко восстанавливать. Нет снимков и отдельного swap-тома.

B LUKS → LVM → ext4

Размеры томов (swap, root) можно менять позже. Нужен хук lvm2.

★ C LUKS → LVM → Btrfs

Подтома, сжатие, мгновенные снимки Snapper: система откатывается, а /home остаётся. Мой выбор; дальше он описан подробнее всех.

D Без шифрования

Для виртуальной машины, стенда, стационарного компьютера в защищённом помещении. Пропускаешь шаг LUKS и вместо /dev/mapper/cryptlvm используешь {{P2}}. На ноутбуке потеря устройства означает потерю данных; шифрование позже без пересоздания разделов не добавить.

Общий шаг: открыть LUKS (A, B, C)

cryptsetup luksFormat --type luks2 {{P2}}
cryptsetup open {{P2}} cryptlvm

Имя cryptlvm одно во всех вариантах: оно будет в параметрах ядра. Пароль запомни, без него данные не прочитать. ESP остаётся незашифрованным: прошивка должна его читать.

Вариант A: ext4 прямо в LUKS

mkfs.ext4 -L ROOT /dev/mapper/cryptlvm

Вариант B: LVM + ext4

pvcreate /dev/mapper/cryptlvm
vgcreate vg0 /dev/mapper/cryptlvm
lvcreate -L {{SWAP}} -n swap vg0           # если нужен дисковый swap (гибернация)
lvcreate -l 100%FREE -n root vg0
mkfs.ext4 -L ROOT /dev/vg0/root
mkswap -L SWAP /dev/vg0/swap

★ Вариант C: LVM + Btrfs

pvcreate /dev/mapper/cryptlvm
vgcreate vg0 /dev/mapper/cryptlvm
lvcreate -L {{SWAP}} -n swap vg0
lvcreate -l 100%FREE -n root vg0
mkfs.btrfs -L MASTER /dev/vg0/root
mkswap -L SWAP /dev/vg0/swap

mount /dev/vg0/root /mnt
for s in @ @home @var_log @var_cache; do btrfs subvolume create /mnt/$s; done
umount /mnt

Подтома: @ (корень), @home (личные данные: откат системы их не трогает), @var_log и @var_cache (логи и кэш не попадают в снимки). Пятый, @snapshots, появится на шаге 9. Дисковый swap отдельным LVM-томом нужен для гибернации: его размер должен быть не меньше ОЗУ. Если гибернация не нужна, делай swap-том меньше или полагайся только на zram.

8 · Монтирование

Wiki: Mount the file systems · Btrfs: mounting subvolumes

Вариант A (ext4 в LUKS)

mount /dev/mapper/cryptlvm /mnt
mount --mkdir -o fmask=0077,dmask=0077 {{P1}} /mnt/efi

Вариант B (LVM, ext4)

mount /dev/vg0/root /mnt
mount --mkdir -o fmask=0077,dmask=0077 {{P1}} /mnt/efi
swapon /dev/vg0/swap

★ Вариант C (LVM, Btrfs)

O=compress=zstd:3
mount -o subvol=@,$O /dev/vg0/root /mnt
mount --mkdir -o subvol=@home,$O      /dev/vg0/root /mnt/home
mount --mkdir -o subvol=@var_log,$O   /dev/vg0/root /mnt/var/log
mount --mkdir -o subvol=@var_cache,$O /dev/vg0/root /mnt/var/cache
mount --mkdir -o fmask=0077,dmask=0077 {{P1}} /mnt/efi
swapon /dev/vg0/swap

compress=zstd:3 экономит место почти бесплатно для процессора; relatime остаётся по умолчанию. ESP монтируется с fmask/dmask 0077: обычные пользователи не читают загрузочный раздел. Без шифрования вместо /dev/mapper/cryptlvm используй {{P2}}.

Snapper до fstab

Snapper при создании конфига делает вложенный подтом .snapshots внутри @. Нам нужен отдельный @snapshots рядом, чтобы откат @ не уничтожил снимки. Поэтому конфиг создаётся сейчас, а подтом переезжает (snap-pac в chroot не ставим: его хук падает без работающего Snapper).

arch-chroot /mnt snapper --no-dbus -c root create-config /
mkdir /btrfs-top
mount -o subvolid=5 /dev/vg0/root /btrfs-top
mv /btrfs-top/@/.snapshots /btrfs-top/@snapshots
umount /btrfs-top; rmdir /btrfs-top
mkdir /mnt/.snapshots
mount -o subvol=@snapshots,compress=zstd:3 /dev/vg0/root /mnt/.snapshots
chmod 750 /mnt/.snapshots

На ArchWiki тот же результат на уже работающей системе достигается так: размонтировать и удалить каталог /.snapshots, выполнить snapper -c root create-config /, затем смонтировать @snapshots на /.snapshots (fstab) и поставить права 750.

fstab

genfstab -U /mnt > /mnt/etc/fstab
nvim /mnt/etc/fstab

11 · initramfs и UKI

Wiki: mkinitcpio · Unified kernel image · Kernel parameters

UKI (Unified Kernel Image) склеивает ядро, initramfs и командную строку в один файл на ESP. Загрузчик просто запускает его; отдельные образы в /boot не нужны. Для UKI используем systemd-initramfs (хук systemd вместо udev): он же даёт запрос пароля, sd-vconsole и возобновление после гибернации без отдельного хука resume.

Хуки

СхемаHOOKS
A (LUKS, ext4)(base systemd autodetect microcode modconf kms keyboard sd-vconsole block sd-encrypt filesystems fsck)
B, ★ C (LVM)(base systemd autodetect microcode modconf kms keyboard sd-vconsole block sd-encrypt lvm2 filesystems fsck)
D (без шифрования, без LVM)(base systemd autodetect microcode modconf kms keyboard sd-vconsole block filesystems fsck)
/etc/mkinitcpio.confconf
MODULES=()
BINARIES=()
FILES=()
HOOKS=(base systemd autodetect microcode modconf kms keyboard sd-vconsole block sd-encrypt lvm2 filesystems fsck)

Порядок важен: сначала sd-vconsole, потом sd-encrypt (открывает LUKS) и после него lvm2 (активирует тома), затем filesystems. ArchWiki для systemd-initramfs называет LVM-хук sd-lvm2; у меня стабильно работает lvm2 (так же в гайде 2.2). Оба варианта допустимы, сверяйся с wiki, если что-то обновится.

Параметры ядра

UUID берём у LUKS-раздела (не у файловой системы внутри него): cryptsetup luksUUID {{P2}}. Для схемы без шифрования и без LVM нужен UUID корня: blkid {{P2}}.

A (LUKS, ext4):

/etc/kernel/cmdlineодна строка
rd.luks.name=<UUID-LUKS>=cryptlvm root=/dev/mapper/cryptlvm rw quiet loglevel=3

B (LUKS, LVM, ext4):

/etc/kernel/cmdlineодна строка
rd.luks.name=<UUID-LUKS>=cryptlvm rd.lvm.lv=vg0/root root=/dev/vg0/root rw quiet loglevel=3

★ C (LUKS, LVM, Btrfs, гибернация):

/etc/kernel/cmdlineодна строка
rd.luks.name=<UUID-LUKS>=cryptlvm rd.lvm.lv=vg0/root rd.lvm.lv=vg0/swap root=/dev/vg0/root rootflags=subvol=/@ rw resume=/dev/vg0/swap quiet loglevel=3 systemd.show_status=error rd.systemd.show_status=error rd.udev.log_level=3

D (без шифрования и LVM): root=UUID=<UUID-ROOT> rw quiet loglevel=3. Без шифрования, но с LVM: как B без rd.luks.name=.

quiet loglevel=3 …show_status=error убирают шум загрузки; для отладки удали их. Пароль в cmdline не пишется никогда. resume= нужен только для гибернации.

default_uki="/efi/EFI/Linux/arch-linux-lts.efi"
default_options="--cmdline /etc/kernel/cmdline"
mkdir -p /efi/EFI/Linux

ls -lh /efi/EFI/Linux/

Старые пресеты с default_image= и fallback замени на строки выше: так в /boot не появятся лишние образы. Формат файла зависит от версии пакета, не заменяй чужой файл вслепую.

Wiki: Arch boot process · Limine · systemd-boot · efibootmgr

Вариант: systemd-boot

systemd-boot сам находит UKI в EFI/Linux на ESP: отдельных записей создавать не надо.

editor no запрещает правку параметров ядра из меню: иначе любой у клавиатуры мог бы запустить систему с init=/bin/sh.

★ Limine

Limine кладёт один файл BOOTX64.EFI на ESP, а конфиг limine.conf лежит в корне ESP. Копия в стандартный путь EFI/BOOT спасёт, если прошивка потеряет запись.

install -Dm644 /usr/share/limine/BOOTX64.EFI /efi/EFI/BOOT/BOOTX64.EFI
efibootmgr --create --disk {{DISK}} --part 1 \
  --label "Arch Linux (Limine)" --loader '\EFI\arch-limine\BOOTX64.EFI' --unicode

--part 1 это номер ESP на диске (подставь свой, если не первый).

/efi/limine.confconf
timeout: 5
default_entry: 1
editor_enabled: no

    protocol: efi

Блок «Arch Linux LTS» нужен, только если ставил запасное ядро.

editor_enabled: no запрещает правку параметров ядра из меню. Чтобы файл загрузчика обновлялся вместе с пакетом, нужен pacman-хук:

/etc/pacman.d/hooks/99-limine-efi.hookhook

[Action]

Exec = /usr/bin/install -Dm644 /usr/share/limine/BOOTX64.EFI /efi/EFI/arch-limine/BOOTX64.EFI

Проверка: efibootmgr -v (запись и путь), ls -lh /efi/EFI/Linux. Если записи нет в меню прошивки, запусти запасной \EFI\BOOT\BOOTX64.EFI.

17 · fish как интерактивная оболочка

Wiki: Fish · Changing your default shell

вариант chsh -s /usr/bin/fish

Проще, но fish становится и login-оболочкой. Скрипты, которые ждут POSIX-оболочку, могут ломаться.

★ Запуск из .bashrc

Login-оболочка остаётся bash (надёжная основа и вход для восстановления), а работаешь ты в fish. Так советует ArchWiki.

sudo pacman -S --needed fish
~/.bashrcbash
if [[ $(ps --no-header --pid=$PPID --format=comm) != "fish" && -z ${BASH_EXECUTION_STRING} && ${SHLVL} == 1 ]]
then
	shopt -q login_shell && LOGIN_OPTION='--login' || LOGIN_OPTION=''
	exec fish $LOGIN_OPTION
fi

Условия: родитель не fish (иначе запуск bash из fish зациклится), это не bash -c (скрипты не перехватываются) и это первая оболочка. На вики показана упрощённая форма (exec fish с проверкой BASH_EXECUTION_STRING), защиту от цикла я добавил сам. Команда bash всегда открывает bash. Root остаётся на bash: так надёжнее для восстановления.

Синтаксис fish другой: статус последней команды это $status, а не $?; переменные set -x VAR значение; подстановка (cmd). Инструкции частей I и II выполняй в bash (live-среда и chroot он и так).

20 · Файрвол

Wiki: nftables · Simple stateful firewall · Security: Firewalls

Простой файрвол с состоянием: входящее запрещено по умолчанию, разрешены ответы на твои соединения, loopback и ICMP. Исходящее не ограничивается. Для ноутбука без серверных служб этого достаточно.

sudo pacman -S --needed nftables
/etc/nftables.confnft
#!/usr/bin/nft -f
destroy table inet filter
table inet filter {
  chain input {
    type filter hook input priority filter
    policy drop

    ct state invalid drop comment "early drop of invalid connections"
    ct state {established, related} accept comment "allow tracked connections"
    iif lo accept comment "allow from loopback"

    meta l4proto { icmp, icmpv6 } accept comment "allow icmp"
    pkttype host limit rate 5/second counter reject with icmpx type admin-prohibited
    counter
  }
  chain forward {
    type filter hook forward priority filter
    policy drop
  }
}
sudo nft -c -f /etc/nftables.conf          # проверка синтаксиса, ничего не применяет
sudo systemctl enable --now nftables.service
sudo nft list ruleset

Служба nftables.service одноразовая: она загружает правила и завершается, поэтому systemctl status показывает inactive (dead), а в логе Finished Netfilter Tables. Это нормально. Работают ли правила, проверяет sudo nft list table inet filter.

destroy table удаляет только свою таблицу inet filter и пересоздаёт её: чужие таблицы (NetworkManager, Docker) остаются нетронутыми, в отличие от flush ruleset (так сделан пакетный /etc/nftables.conf, смотри его вики-страницу). Если позже включишь службу, слушающую порт (SSH, веб-сервер), открой нужный порт в цепочке input, иначе доступа не будет. ★ У меня точка доступа и Tailscale добавляют свои правила: это часть III (deploy.sh заменит этот файл версией с ними).

22 · Менеджер входа Ly

Wiki: Ly · Display manager

Ly это минимальный менеджер входа прямо на TTY. Он нужен, чтобы вход выглядел одинаково и для консоли, и для любой графики. Пока в системе нет графических сессий, он предлагает пункт shell.

23 · Критерий «база готова»

  • Система грузится с запросом пароля LUKS и открывает fish (через Ly или tty1).
  • Работают сеть (nmcli), обновления (sudo pacman -Syu), zram и дисковый swap.
  • Установлены tmux, neovim, btop, fastfetch, yazi; шрифт и раскладка консоли правильные.
  • Файрвол включён: sudo nft list ruleset показывает policy drop во входящей цепочке.
  • Есть снимок «base ok», а snap-pac делает пары снимков при обновлениях.

Это и есть моя база: она одинаково воспроизводится на любой машине и годится как отправная точка для любой графической среды.

27 · Профиль машины

Файлы, зависящие от машины (твой UUID LUKS, модули железа, микрокод), лежат в hosts/<имя-машины>/. Для своей машины создай каталог с тем же именем, что /etc/hostname:

git clone <URL-репозитория> ~/Projects/zen
cd ~/Projects/zen
H=hosts/$(cat /etc/hostname)
mkdir -p $H/etc/kernel
cp /etc/kernel/cmdline    $H/etc/kernel/cmdline
cp /etc/mkinitcpio.conf   $H/etc/mkinitcpio.conf
printf '%s\n' {{UCODE}} snapper snap-pac > $H/packages.txt

Эти файлы личные. В cmdline лежит UUID раздела. Если форкаешь репозиторий, держи профиль своей машины в приватной копии или в .gitignore.

Без профиля применяются только общие файлы, а загрузка (cmdline, initramfs) остаётся как у тебя.

Для A и B: открой LUKS, (для B) vgchange -ay vg0, затем mount /dev/mapper/cryptlvm /mnt (A) или mount /dev/vg0/root /mnt (B), ESP в /mnt/efi. Без шифрования пропусти cryptsetup.

Если не грузится после обновления, выбери в меню запасное ядро (LTS). Если ломается initramfs, сверь хуки (шаг 11) и UUID в cmdline.
